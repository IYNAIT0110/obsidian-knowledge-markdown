# 术语速查与操作清单

## 一、核心术语

| 术语 | 中文直觉 | 不要误解为 |
|---|---|---|
| Model | 会生成和判断的大脑 | 完整工作人员 |
| Token | 模型处理文本的计量单位 | 字数的完全等价物 |
| API | 软件间调用协议 | 一个具体模型 |
| API Key | 调用凭证与计费身份 | 可公开配置 |
| Agent | 模型 + 规则 + 工具 + 状态 + 循环 | 单次回复 |
| Agent Loop | 观察、判断、行动、再观察 | 固定一次流程 |
| Tool | 可实际执行的能力 | 一段知识 |
| Skill | 专业知识与流程 | 必然执行动作的程序 |
| Session | 当前任务事件 | 永久知识库 |
| Harness | Agent 运行底座 | 多 Agent 平台 |
| Workflow | 做事步骤 | Branch + Worktree |
| Git | 版本历史系统 | GitHub 网站 |
| GitHub | 在线托管与协作 | 本地 Git 替代品 |
| Branch | 逻辑开发路线 | 物理目录 |
| Worktree | 同仓库的额外工作目录 | 完全独立仓库 |
| Multica | 多 Agent 编排平台 | 单 Agent 内部核心 |
| Linear | Issue/项目管理 | 代码版本控制 |
| Dashi Taskboard | 轻量 Agent 任务看板 | 模型或 Runtime |
| Local Model | 本机模型 | 不处理 Token |
| Runtime | 运行模型或 Agent 的程序 | 权重文件 |

## 二、是否需要新 Agent / 对话

满足越多越值得新建：目标独立、产物独立、可单独验收、可并行、共享背景少、需要不同角色、失败不阻塞全部。

## 三、是否需要 Branch

会修改代码、需要审核、可能回滚、与主线不同步、独立功能或 Bug 修复时使用。纯讨论和只读研究通常不需要。

## 四、是否需要 Worktree

多个代码任务同时进行、不想频繁切 Branch、多 Agent 并行修改、需要同时构建或目录隔离时使用。

## 五、Agent 交接模板

```markdown
# 任务
一句话目标。

## 背景
只保留必要信息。

## 范围
允许修改哪些文件。

## 不在范围
明确不要做什么。

## 输入 / 输出 / 验收 / 风险
写成可检查条目。
```

## 六、API Key 安全

- [ ] 不写进前端；
- [ ] 不提交 Git；
- [ ] 不贴进聊天或截图；
- [ ] 使用环境变量或安全凭证；
- [ ] 不同应用不同 Key；
- [ ] 配置额度上限；
- [ ] 日志脱敏；
- [ ] 可撤销和轮换。

## 七、Git / Worktree 速查

```bash
git status
git switch -c feature/example
git branch
git worktree add ../project-example -b feature/example
git worktree list
git worktree remove ../project-example
```

> [!warning]
> 删除 Worktree、Branch 或文件前，先确认工作已提交、已合并、路径准确。

## 八、GH Agent 清单

- [ ] 定义可验证问题；
- [ ] 先做只读 GH API；
- [ ] C# 规则产生结构化摘要；
- [ ] Tool 有 Schema；
- [ ] 修改需确认、可撤销；
- [ ] Session 可追溯；
- [ ] Runtime 与 Rhino 隔离；
- [ ] 本地与云端模式说明清楚；
- [ ] 记录 Token、延迟和正确率。

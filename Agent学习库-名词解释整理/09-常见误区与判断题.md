# 常见误区与判断题

## 一、常见误区

1. **模型会直接操作电脑**：实际由 Runtime 执行工具，权限和 Sandbox 限制范围。
2. **插件调用 AI API 就是 Agent**：一次调用通常只是 AI 功能；持续目标、工具、状态和循环才是关键。
3. **新开 Codex 对话就是新 Workflow**：新对话是新上下文，Workflow 是做事步骤。
4. **Workflow = Branch + Worktree**：二者只是代码和目录隔离手段。
5. **每个小功能都必须独立一套**：只为可独立交付、可并行且足够大的工作包拆分。
6. **Worktree 是完整复制的新仓库**：它与其他 Worktree 共享底层 Git 仓库对象和历史。
7. **本地模型不使用 Token**：仍按 Token 处理上下文，只是不一定向云端按 Token 付费。
8. **把模型塞进 GH 插件最方便**：可统一安装，但 Runtime 最好独立进程。
9. **Agent 越多越强**：还会增加上下文、协调和合并成本。
10. **Multica 与 Harness 二选一**：可上下组合，一个管多 Agent，一个管单 Agent 内部。

## 二、判断题

1. API 就是大模型本身。  
   **错。** API 是调用约定。

2. 一个 Codex 对话通常可视为独立工作上下文。  
   **对。** 但不必然对应 Branch 或 Worktree。

3. Branch 会自动创建另一个物理文件夹。  
   **错。** Worktree 才提供额外目录。

4. 多 Agent 并行一定更省 Token。  
   **错。** 可能更贵，也可能提高有效产出。

5. 工具越多，Agent 一定越强。  
   **错。** 工具说明占上下文，重叠工具会造成选择困难。

6. GH Data Tree 统计应先由确定性代码完成。  
   **对。**

7. Private GitHub 仓库在任何情况下都绝对安全。  
   **错。** 仍取决于账号、Key、成员权限和供应链安全。

8. 本地模型与 Local Runtime 是同一个概念。  
   **错。**

9. 只读研究任务通常不需要单独 Worktree。  
   **对。**

10. Agent 的 UI 就是 Agent 的全部。  
    **错。**

## 三、情境练习

- 同时开发 GH Plugin UI 和 Agent Runtime，接口已约定：可用两个对话、两条 Branch、两个 Worktree。
- 只改一条按钮文案：不必独立一整套。
- GH 文件高度保密：规则分析 + 本地 Runtime + 本地模型，禁用或严格控制云端。
- 上下文越来越长：稳定知识写入 Skill，事实压缩成 Session 摘要，工具先筛选日志。

## 四、最终口述题

- 模型、API、Agent、Harness 的关系是什么？
- Agent Loop 为什么是发动机？
- Branch 和 Worktree 分别解决什么？
- 新 Codex 对话与新 Workflow 有何不同？
- Multica 与 DeepSeek Harness 为什么相似又不同？
- 怎样给多 Agent 分工最省 Token？
- GH Agent 为什么先规则分析、再本地模型、最后云端模型？
